## 1. 开始使用

### 1.1 账号与角色

系统内置 4 个演示账号，密码仅用于开发环境，生产部署前必须修改。

| 账号 | 密码 | 角色 | 所属工厂 | 权限项 | 一句话职责 |
| --- | --- | --- | --- | ---: | --- |
| `admin` | `Admin@123` | ADMIN 系统管理员 | — | 52 | 管人、管权限、管数据同步 |
| `sales01` | `Sales@123` | SALES 销售 | 示范工厂 F001 | 18 | 管客户、管订单、发起申请 |
| `manager01` | `Manager@123` | FACTORY_MANAGER 厂长 | 示范工厂 F001 | 29 | 管设备、管排产、管仓储 |
| `finance01` | `Finance@123` | FINANCE 财务 | 不绑定工厂（全局） | 33 | 管合同、管钱、管审批 |
| （待建） | — | OPERATOR 操作员 | 示范工厂 F001 | 10 | 登记点检、领料出库 |

> 财务账号**不绑定工厂**，因此天然拥有全局数据范围；销售、厂长、操作员都绑定在具体工厂上。

### 1.2 登录

打开 `http://你的IP地址:5173`，PC Web 登录页只提供一个入口按钮，密码只提交给认证中心，业务页面不接触口令。

![PC Web 登录页](screenshots/common-login.png)

点击「**使用统一身份认证登录**」后跳转到认证中心：

![认证中心登录页](screenshots/common-auth-login.png)

输入账号密码后回调到 PC Web，自动进入工作台。完整鉴权链路见 [1.4](#14-权限是如何生效的)。

> 令牌过期后需要重新登录（公共客户端不签发 refresh token）。**管理员调整过你的权限后，也必须重新登录**，旧 JWT 里的权限声明不会自动刷新。

### 1.3 界面结构

以管理员工作台为例，左侧是分组菜单，右侧是内容区，顶部是面包屑、消息铃铛、全屏按钮和账号信息。

![工作台（管理员）](screenshots/admin-dashboard.png)

| 区域 | 说明 |
| --- | --- |
| 顶部左侧 | 面包屑（首页 / 当前页）与侧边栏折叠按钮 |
| 顶部右侧 | 日期、消息铃铛（未读数 + 最近 5 条）、全屏、当前账号与角色、退出 |
| 左侧菜单 | 按「工作台 / 消息中心 / AI 助手 / 经营大屏 / 订单管理 / 生产管理 / 财务管理 / 仓储管理 / 流程审批」分组；**菜单项按权限显示** |
| 内容区 | 页头（模块标签 + 标题 + 说明 + 主操作按钮）、指标卡、表格/图表 |
| 左下角 | 统一认证连接状态与版本标识（V1.4 · PC Web） |

**注意菜单差异**：管理员左侧有「经营大屏」，销售左侧没有——因为大屏需要 `bi:cockpit:read` 权限。

### 1.4 权限是如何生效的

![统一认证与鉴权流程](diagrams/login-flow.svg)

关键结论：

1. 前端隐藏菜单和按钮**只是体验优化**，不是安全边界；
2. 每个后端接口都独立用 `@PreAuthorize` 校验权限码，失败返回 403；
3. 通过权限校验后，服务端还会按用户角色追加**数据范围过滤**，再查数据库。

### 1.5 个人中心

![个人中心](screenshots/admin-profile.png)

- 「我的权限」区块按业务域列出本账号拥有的权限项，并给出总数；
- 右侧「当前会话」展示令牌类型、签发/过期时间、剩余时长与 Scope；
- 页面底部提示：**公开客户端默认不签发 refresh token**，访问令牌约 30 分钟过期，到期后接口返回 401，需要重新登录；
- 角色与权限由管理员在后台维护，普通用户只能查看。

同一页面在不同角色下的权限清单长度完全不同，这正是「同一个网址、不同的人看到不同内容」的直观体现：

## 2. 权限与数据范围

### 2.1 角色权限矩阵

![角色权限矩阵](diagrams/permission-matrix.svg)

| 符号 | 含义 |
| --- | --- |
| ● | 全部操作（可新增 / 修改） |
| ◐ | 部分操作（可提交或可审批） |
| ○ | 只读 |
| — | 无权限，菜单不显示、接口返回 403 |

> 矩阵以种子账号的授权为准。管理员可在「角色与权限」页面查看并调整。

### 2.2 数据范围

![数据范围规则](diagrams/data-scope.svg)

| 范围 | 适用角色 | 能看到的数据 |
| --- | --- | --- |
| 全局 ORG | ADMIN、FINANCE、服务账号 | 全部工厂的客户、订单、财务数据 |
| 工厂 FACTORY | FACTORY_MANAGER | 仅本工厂的设备、工单、队列、仓储 |
| 本人 OWN | SALES、OPERATOR | 仅归属自己的客户、自己创建的订单 |

销售的新建客户会被后端强制收敛为「归属本人、信用额度 0」，额度只能通过审批中心调整。

### 2.3 越权会怎样

销售直接访问 `/cockpit`（经营大屏）时，路由守卫会拦到「无访问权限」页，并明确告知缺哪个权限码：

![销售访问经营大屏被拦截](screenshots/sales-forbidden.png)

同样地，销售访问 `/finance/credit`（信用看板）也会被拦截：

![销售访问信用看板被拦截](screenshots/sales-forbidden-credit.png)

> 页面底部提示「权限变更后需要重新登录以获取新的 JWT」——这是最常见的「我明明有权限却看不到」原因。

## 3. 管理员（ADMIN）

管理员拥有全部 52 项权限，目标不是日常录入，而是**授权、兜底、巡检**。

![管理员工作台](screenshots/admin-dashboard.png)

### 3.1 用户账号与授权

![用户账号](screenshots/admin-user-list.png)

- 「用户账号」页维护账号、归属工厂与角色绑定；
- 角色决定权限集合，权限调整后该用户**必须重新登录**才会生效；
- 生产环境建议关闭种子数据开关（`app.seed.enabled=false`），改由本页创建账号。

![角色与权限矩阵](screenshots/admin-permission-matrix.png)

- 「角色与权限」页以矩阵形式呈现「角色 × 权限码」，可逐项勾选；
- 权限码按业务域前缀划分：`customer:` / `finance:` / `order:` / `production:` / `equipment:` / `warehouse:` / `approval:` / `system:` / `ai:` / `bi:`。

### 3.2 工厂组织

![工厂组织](screenshots/admin-factory-list.png)

工厂是订单排产、设备归属、仓储主仓的数据边界。订单不能跨工厂；每个工厂至少要有一个主仓。

### 3.3 审批中心（兜底处理）

![审批中心](screenshots/admin-approval-center.png)

- 「我的待办」按指定审批人或审批角色命中待办；「我的申请」查看自己提交的申请；
- 同意时由审批中心回调业务服务落地变更（信用额度调整、队列插队、费用报销、借款放款）；
- 驳回**必须填写意见**；申请人可撤销自己的待审批申请。

### 3.4 经营大屏与 BI 同步

![经营大屏（管理员）](screenshots/admin-cockpit.png)

- 16:9 暗色大屏，数据全部来自 `platform-bi` 只读聚合接口；
- 默认每 **5 分钟**自动刷新，支持浏览器全屏，适合会议/看板投放；
- 数据过期时顶部会出现陈旧数据提示条；
- 不可计算的指标不会显示成 0，而是进入「待数据源」清单；
- 管理员可手动触发一次 BI 数据同步（`POST /api/bi/admin/refresh`，需 `bi:etl:run` 权限）。

### 3.5 消息中心

![消息中心](screenshots/admin-message-center.png)

站内消息用于推送排队顺延、交期风险、审批结果等。顶部铃铛显示未读数，页面路由切换和 30 秒轮询都会刷新。

### 3.6 管理员页面速查图册

管理员可访问全部业务页面。下图把未在上文展开的页面集中列出，便于新同事快速熟悉系统全貌。

## 4. 销售（SALES）

销售负责「单」：客户 → 合同关联 → 订单 → 跟进交期。

![销售工作台](screenshots/sales-dashboard.png)

### 4.1 能做与不能做

| 可以 | 不可以 |
| --- | --- |
| 新建/维护**自己名下**的客户 | 查看他人客户、修改信用额度 |
| 选客户 + 财务已录入的合同下单 | 查看信用看板、合同管理、收款核销、开票、对账 |
| 查看排产队列、申请插队 | 直接改动队列（需厂长审批） |
| 提交费用报销、借款 | 审批、付款、放款 |
| 查看（只读）应收账款、维护工单、点检记录 | 仓储出入库、设备台账编辑 |
| 使用 AI 助手、查看工作台经营指标 | 经营大屏 |

### 4.2 建客户

![新建客户](screenshots/sales-customer-create.png)

1. 客户**来源**与**归属业务员**必填；
2. 销售新建时，归属被后端收紧为本人，信用额度收敛为 0；
3. 客户名称、归属、信用额度、结算方式、开票信息属于**审批字段**，普通编辑框不提供直接修改入口——需要调整额度请走审批中心。

![客户列表](screenshots/sales-customer-list.png)

客户 360 页把档案、合同、应收、信用与订单放在一屏：

![客户 360（销售）](screenshots/sales-customer-detail.png)

### 4.3 建订单

![新建订单](screenshots/sales-order-create.png)

1. 必须选择**合作中**客户和**财务已录入**的合同；
2. 订单不能跨工厂；
3. 提交时后端强校验：客户状态、合同归属/状态/有效期/币种/剩余额度、信用额度与「逾期 30 天」规则，页面只做提示，最终以服务端为准；
4. 订单号是雪花 ID，前端按字符串处理（不要转 `Number`）。

![订单列表](screenshots/sales-order-list.png)

![订单详情](screenshots/sales-order-detail.png)

订单详情含「生产工单」区块：设备、队列位置、计划/实际时间、状态与备注，订单状态随工单联动更新。

### 4.4 排产队列与插队申请

![排产队列（销售视角）](screenshots/sales-production-schedule.png)

销售是**只读**视角：可以看每台设备的生产中/等待队列、队列位置、计划时间，据此判断交期风险。

![插队申请](screenshots/sales-queue-jump.png)

1. 只有销售能对自己**排队中**的工单发起插队申请；
2. 目标位置必须**早于**当前位置；
3. 申请提交到审批中心，厂长/管理员审批通过后队列立即重排；
4. 被顺延业务员和申请人都收到站内消息，**系统不做经济补偿**；
5. 插队申请页是只读记录页，审批动作在「审批中心 · 我的待办」完成。

### 4.5 费用报销与借款

![费用报销](screenshots/sales-expense-list.png)

![借款与还款](screenshots/sales-loan-list.png)

销售只能**提交**单据，不能审批、付款或放款。金额按元输入、按分存储并截断，不做四舍五入。

销售对**应收账款**只有只读权限，用于自查欠款与账龄：

![应收账款（销售只读）](screenshots/sales-receivable-list.png)

销售对**维护工单**与**点检保养**同样只有只读权限，用于判断交期风险：

![维护工单（销售只读）](screenshots/sales-maintenance-list.png)

![点检保养（销售只读）](screenshots/sales-inspection-list.png)

### 4.6 审批中心

![审批中心（销售）](screenshots/sales-approval-center.png)

销售在「我的申请」里跟踪进度；驳回时必须阅读审批意见。

### 4.7 消息中心

![消息中心（销售）](screenshots/sales-message-center.png)

销售收到的站内消息主要是三类：队列顺延通知、交期风险提醒、审批结果通知。

### 4.8 AI 助手（只读）

![AI 助手](screenshots/sales-ai-assistant.png)

- 可查询订单、应收、报销、借款、审批待办；
- **只读**：不自动审批、不付款、不改信用、不排产，也不在生产库上直接跑模型 SQL；
- 工具调用会透传当前用户 JWT，因此**不会绕过数据范围**；
- 对话审计写入 `ai_chat_log`。

## 5. 厂长（FACTORY_MANAGER）

厂长负责「产」：设备 → 工单 → 队列 → 维护点检 → 仓储。

![厂长工作台](screenshots/manager-dashboard.png)

### 5.1 经营大屏（本厂范围）

![经营大屏（厂长）](screenshots/manager-cockpit.png)

厂长拥有 `bi:cockpit:read`，可看 16:9 大屏；数据范围为本工厂，设备状态与工厂对比只反映本厂。

### 5.2 设备台账

![设备台账](screenshots/manager-equipment-list.png)

- 设备编号全公司唯一，归属单一工厂，**创建后不可修改**；
- 设备状态只有 `IDLE / RUNNING / MAINTENANCE / FAULT / DISABLED`；
- `RUNNING` 只能由「开始工单」进入，页面只允许人工切换空闲/保养/故障/停用，**生产中的设备不能停机**；
- 停机时若仍有等待队列，队列保留并给相关业务员发交期风险消息。

### 5.3 排产队列

![排产队列（厂长）](screenshots/manager-production-schedule.png)

这是厂长的主工作台。页面按设备分组展示当前生产与等待队列，**队列位置从 1 开始**。

| 操作 | 说明 |
| --- | --- |
| 新建工单 | 可先不选设备，进入「待排产」后再分配 |
| 开始队首工单 | 只有队首可以开工，一台设备同一时间只能处理一笔订单 |
| 完成工单 | 完成后订单状态联动更新 |
| 取消排队中工单 | 仅限尚未开工的工单 |

设备必须与订单**同工厂**，并满足材料、门幅和工艺要求；不符合时由后端拒绝入队，页面只做提示。超出设备产能的订单进入 **FIFO 队列**。

### 5.4 维护工单

![维护工单](screenshots/manager-maintenance-list.png)

1. 维护工单由**厂长或管理员**发起，新建时设备状态不变；
2. 「开始维护」后设备转为「保养中 / 故障维修」，等待队列保留并给受影响业务员发交期风险消息；
3. 「完成维护」登记成本与停机时长，设备恢复空闲并重算队列计划时间；
4. 维护费用全部由公司承担，只做成本记录，**不生成应收、不计算设备使用费**。

### 5.5 点检保养

![点检保养](screenshots/manager-inspection-list.png)

- 供操作员登记日/周/月点检结果；结果为异常时必须填写异常项数；
- 异常可一键生成「点检整改」维护工单；
- 销售和财务对维护与点检只有只读权限：销售用于判断交期风险，财务用于了解维保成本。

### 5.6 仓储

![仓储管理](screenshots/manager-warehouse.png)

包含**仓库档案、物料档案、库存台账**三个页签：每厂至少一个主仓，物料单价 4 位小数、损耗率 2 位小数，库存台账只读且不提供调整入口。

![采购入库](screenshots/manager-purchase-receipt.png)

采购入库先建草稿再确认收货：单价和损耗率取自物料档案，金额由服务端按「数量 × 单价」**截断到分**，收货后单据不可修改。材料成本只有采购入库这一个来源。

![工单领料](screenshots/manager-material-issue.png)

工单领料建单**不扣库存**，确认发料才扣减并计入工单材料成本；领料仓库必须与工单同厂，工单需处于排队中或生产中。工单材料成本只对拥有 `production:cost:read` 的角色展示（厂长、管理员、财务）。

### 5.7 插队审批

![插队申请（厂长视角）](screenshots/manager-queue-jump.png)

厂长拥有 `production:queue:jump:approve`，在「审批中心 · 我的待办」里处理销售的插队申请。审批通过后队列立即重排并推送站内消息。

![审批中心（厂长）](screenshots/manager-approval-center.png)

### 5.8 设备数据上报

![设备数据上报](screenshots/manager-device-report.png)

查看 MQTT / CoAP / HTTP 三条通道的上报数据、订单图片一条一单的匹配情况，以及 OCR 订单号未匹配的暂存。

### 5.9 订单（只读）

![订单列表（厂长）](screenshots/manager-order-list.png)

厂长拥有 `order:read` 可查看订单以掌握交期与生产进度，但**没有 `order:create`**，不能新建订单。

### 5.10 AI 助手（只读）

![AI 助手（厂长）](screenshots/manager-ai-assistant.png)

可查询订单、应收、报销、借款与审批待办；工具调用透传当前用户 JWT，不会越权访问其他工厂数据。

## 6. 财务（FINANCE）

财务负责「钱」：合同 → 信用 → 应收收款 → 开票对账 → 放款还款。财务账号**不绑定工厂**，数据范围是全局。

![财务工作台](screenshots/finance-dashboard.png)

### 6.1 合同录入（订单的前置条件）

![合同管理](screenshots/finance-contract-list.png)

1. 合同由**财务**新建，初始状态是「待财务录入」；
2. 点击「正式录入」或「保存并正式录入」后，订单才能引用；
3. 订单提交时会校验合同的归属、状态、有效期、币种和剩余额度；
4. 合同剩余额度会限制可开票金额。

### 6.2 信用看板

![信用看板](screenshots/finance-credit.png)

逐客户合并「**未收应收**」和「**未关闭订单占用**」，展示授信、已用、可用、最大逾期与风险标签。页面**只读**，不提供直接改额度的入口——调额度走审批中心。

### 6.3 应收账款与收款核销

![应收账款](screenshots/finance-receivable-list.png)

- 展示账龄与逾期（后端实时计算），并按筛选条件汇总应收总额、未收余额和逾期金额；
- 「登记应收」只对财务开放；正式应收由发货/开票自动生成。

![收款核销](screenshots/finance-receipt-list.png)

1. 先登记到账，再按未结应收分配；
2. 一张收款单可核销多张应收；
3. 未核销余额作为**预收待认领**；
4. 前端用 `BigInt` 比较金额，避免浮点误差。

### 6.4 手工开票与客户对账

![手工开票](screenshots/finance-invoice-list.png)

- 登记票面信息并跟踪「已登记 → 已寄出 → 客户签收」；
- 发票号码全局唯一，开票金额受合同剩余额度限制；
- 作废/红冲待审批中心上线后开放。

![客户对账](screenshots/finance-statement-list.png)

按客户和期间生成快照，展示期初、本期应收、本期收款、本期开票和期末；明细包括应收、核销和开票流水，可打印/另存 PDF，客户确认后归档。

### 6.5 报销付款与借款放款

![费用报销（财务）](screenshots/finance-expense-list.png)

![借款与还款（财务）](screenshots/finance-loan-list.png)

财务独有 `finance:expense:pay`、`finance:loan:disburse`、`finance:loan:repay`：**审批通过后由财务放款 / 还款登记**。其他角色只能提交。

### 6.6 审批流程与金额档位

![审批流程与档位](screenshots/finance-approval-definition.png)

- 由财务维护：同一业务类型可配置多档，按「**下限含、上限不含**」匹配，优先级数字小的先命中；
- 金额按元输入、按分存储。

### 6.7 审批中心（财务是审批主力）

![审批中心（财务）](screenshots/finance-approval-center.png)

财务拥有 `approval:approve` / `approval:manage` / `approval:apply`，可审批信用额度调整、队列插队、费用报销、借款四类业务，并在审批通过后由审批中心回调业务服务落地变更。

### 6.8 财务的其余视角

财务同样拥有 `bi:cockpit:read`，可以看经营大屏（含成本毛利指标，需 `bi:cost:read`）：

![经营大屏（财务）](screenshots/finance-cockpit.png)

客户与订单对财务是**只读**的，用于核对收款与发运：

![客户列表（财务只读）](screenshots/finance-customer-list.png)

![订单列表（财务只读）](screenshots/finance-order-list.png)

### 6.9 AI 助手（只读）

![AI 助手（财务）](screenshots/finance-ai-assistant.png)

财务可用助手快速汇总应收、借款与审批待办；助手只做查询与摘要，不会替财务审批、放款或改额度。

```powershell
# 1. 初始化数据库（按 01 → 18 顺序执行 sql/ 下的脚本）
```

### 8.4 常见问题

| 现象 | 处理 |
| --- | --- |
| 登录页报 401 | 确认认证中心已启动、`pc-web` 客户端已注册当前回调地址 |

### 9.2 通用业务红线

| 红线 | 说明 |
| --- | --- |
| 金额只截断不四舍五入 | 所有金额以**分**为单位存储；长度保留 2 位小数并截断；物料单价 4 位小数 |
| 材料成本唯一来源 | 只来自仓库的**采购入库**单据，不允许手工录入 |
| 信用占用 | 未收应收 + 已确认未出库订单共同占用授信额度 |
| 逾期 30 天 | 逾期超过 30 天禁止下单与发货 |
| 订单必须挂合同 | 订单创建前合同必须是财务「已录入」状态 |
| 队列 FIFO | 同设备同一时间只处理一笔订单，超产能进入队列按先后执行 |
| 审批前置 | 信用额度调整、队列插队、费用报销、借款都必须走审批中心 |
| 权限不缓存 | 权限变更必须重新登录才生效 |
